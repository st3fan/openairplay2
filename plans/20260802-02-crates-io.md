# Publish openairplay2 to crates.io

Goal: make `openairplay2` installable as a normal crates.io dependency
(`openairplay2 = "0.1"`) instead of a git reference, with docs on
docs.rs, and make releasing repeatable. Research findings first, then
the work; the code changes themselves are small — most of this is
metadata, documentation, and automation.

## Research findings (2026-08-02)

**Ready already:**

- The crate names `openairplay2` (and `openairplay2-receiver`) are
  **unclaimed** on crates.io.
- Licensing housekeeping is done: `LICENSE` (MIT) and `NOTICE.md`
  (shairport-sync attribution + FairPlay quarantine) exist at the repo
  root, and `license = "MIT"` is declared.
- `cargo package -p openairplay2` succeeds; the package is small
  (source + a 4.7 KB AAC test fixture). All dependencies are crates.io
  releases (no git/path deps in the library) and pure Rust — no system
  libraries — so **docs.rs will build it without special metadata**,
  and so will any consumer on any platform.

**Gaps:**

- `Cargo.toml` lacks discovery/linkage metadata — cargo warns "no
  documentation, homepage or repository". Missing: `repository`,
  `readme`, `keywords`, `categories`, `rust-version`.
- `LICENSE` and `NOTICE.md` live at the workspace root, so they are
  **not included in the published package** (the package only picks up
  the crate directory). `NOTICE.md` matters: `fairplay.rs` ships in
  the crate, and its attribution should travel with it.
- `RUSTDOCFLAGS="-W missing_docs"` reports **15 undocumented public
  items** — the API works but the docs.rs page would have holes.
- **No CI at all** (`.github/workflows/` doesn't exist). The "library
  must stay macOS-green" deliverable is enforced only by discipline,
  and there is no release automation.
- `openairplay2-receiver`'s path dependency has no `version`, so the
  binary crate as-is cannot be published (fine unless we choose to).

**Decisions for Stefan (the plan assumes the recommended defaults):**

1. **Publishing the FairPlay tables.** `fairplay.rs` (the canned
   `fp-setup` reply tables, Apple-derived interop constants) would now
   be redistributed via crates.io, not just GitHub. This is the same
   gray area notes/licensing.md documents — NOTICE.md attributes and
   quarantines them, every hobby receiver ships equivalents, and
   crates.io policy doesn't forbid it, but it is Stefan's call to
   accept. *Recommendation: publish as-is with NOTICE.md included in
   the package.*
2. **Publish the receiver binary crate too?** Publishing
   `openairplay2-receiver` enables `cargo install openairplay2-receiver`
   on Linux. *Recommendation: yes, but as the last phase — it is cheap
   once the library is up (add `version` to the path dep).*
3. **Radio's dependency** can later switch from the git reference to
   the published version — out of scope here, radio-side change.

## Scope

In scope: crate metadata, packaging the license/notice files, a
documentation pass, CI (test/clippy/fmt on Linux **and** macOS — the
portability deliverable, finally enforced), release automation via
crates.io **Trusted Publishing** (GitHub OIDC — no long-lived API
token secret), a short releasing runbook, and the `v0.1.0` release
itself.

Out of scope: any behavior change; README rewrites beyond what
publishing needs; radio's switch to the published crate; docs.rs
feature flags (the crate has no features).

## Phases

1. **Packaging metadata.** `openairplay2/Cargo.toml`: add
   `repository`, `readme = "../README.md"`, `keywords`
   (e.g. `airplay`, `airplay2`, `audio`, `receiver`, `raop`),
   `categories` (e.g. `multimedia::audio`, `network-programming`),
   `rust-version` (the floor CI tests). Ship `LICENSE` + `NOTICE.md`
   inside the package (symlink or copy into the crate dir, listed in
   `include`/not excluded — verify with `cargo package --list`).
   Acceptance: `cargo publish --dry-run -p openairplay2` clean, no
   manifest warnings, license/notice visible in `--list`.

2. **Documentation pass.** Add `#![warn(missing_docs)]` to `lib.rs`
   and document the 15 missing public items; re-read the crate-level
   docs as a first-time embedder would (the README embedding example
   and lib.rs example already exist and stay the canonical ones).
   Acceptance: zero missing-docs warnings; `cargo doc --no-deps`
   clean.

3. **CI + release automation.** `ci.yml`: build, test, clippy, fmt on
   `ubuntu-latest` (with `libasound2-dev`, whole workspace) and
   `macos-latest` (`cargo test -p openairplay2` — the portable
   subset), on PRs and main. `release.yml`: on pushing a `v*` tag,
   run tests then `cargo publish` using crates.io Trusted Publishing
   (configure the GitHub repo/workflow as the trusted publisher on
   crates.io — first publish may need a manual `cargo publish` with a
   token to create the crate before trust can be configured; the
   runbook covers this). Add `runbooks/releasing.md`: bump version,
   update status notes, tag, verify docs.rs. Acceptance: CI green on
   both OSes; a dry-run of the release path.

4. **Release `v0.1.0`, then the receiver (optional, per decision 2).**
   Publish the library (Stefan triggers — tag push or first manual
   publish), verify the crates.io page and docs.rs render, README gets
   the crates.io/docs.rs badges and an "add it to Cargo.toml" line.
   Then `openairplay2-receiver`: add `version = "0.1"` to the path
   dependency, same metadata treatment, publish.

## Test strategy

Phases 1–2 are verified by cargo itself (`publish --dry-run`,
`package --list`, doc builds) — no behavior changes, the full existing
suite must stay green. Phase 3 is verified by the workflows running on
the PRs that introduce them (CI proves CI). Phase 4 by the live
crates.io page, `docs.rs/openairplay2` rendering, and a scratch
project depending on `openairplay2 = "0.1"` building the lib.rs
example.

## Acceptance criteria

- `cargo publish --dry-run -p openairplay2` passes with no warnings;
  the packaged crate contains `LICENSE` and `NOTICE.md`.
- Zero `missing_docs` warnings; docs.rs builds and renders.
- CI runs test/clippy/fmt on Linux and macOS for every PR; releasing
  is a tag push (after one-time trusted-publisher setup), documented
  in a runbook.
- `openairplay2 = "0.1"` from crates.io compiles the README embedding
  example; the identity/`AudioSink`/event contracts are unchanged.
